# agentvoice

[![check](https://github.com/duaneoca/agent-voice/actions/workflows/check.yml/badge.svg)](https://github.com/duaneoca/agent-voice/actions/workflows/check.yml)

A drop in voice extension for Omarchy. Gives whatever AI agent is
installed on the box a natural voice interface: wake word or push to
talk in, spoken replies out. Claude Code is the first target, not the
only one.

![Left, the bar panel: the switch, the microphone level against its gate with a Mute button, the agents, five quick switches, the voice, what the agent may do, and the last exchange. Right, the settings on their Overview page: the service, the microphone, each agent and what it is doing, and the last exchange](preview.png)

Omarchy already ships dictation. Voxtype gives it push to talk on F9,
running whisper.cpp locally, with a Dictation indicator in the bar.
agentvoice is the other half: a wake word instead of a keypress, an
agent instead of a text field, and an answer spoken back.

## Install

The bar widget is an Omarchy shell plugin, so it arrives the usual way:

```bash
omarchy plugin add https://github.com/duaneoca/agent-voice.git --enable
```

That gets you the icon and the settings screen. The thing that listens is a
Python daemon with a few hundred megabytes of models behind it, so it is a
second, explicit step -- the way Omarchy installs Voxtype:

```bash
~/.config/omarchy/plugins/duaneoca.agentvoice/install.sh
```

It needs one system package, `uv` from the official `extra` repo, and then
manages its own CPython. Nothing is installed against the system interpreter:
Arch is a rolling release, and a venv built on `/usr/bin/python` stops
importing the next time Arch bumps it, which would leave voice silently dead
after an `omarchy update`.

Roughly 750MB with the default engine, or 900MB with openWakeWord as well.
openWakeWord is not installed by default and the installer does not ask: it is
optional, and a question with Yes preselected is not really optional. Choose it
under **Engine** in the settings and it offers to fetch it, or run the
installer again with `--oww`. sherpa-onnx works the same way, with
`--sherpa`: about 60MB, package and model.

The widget and the engine are two installs, because Omarchy runs
nothing on a plugin's behalf: `plugin add` clones a directory and
`plugin remove` deletes one, with no hook in between. So the widget owns
both halves instead. Add it, open it, and it offers to install the
engine; the settings' **About** page has a **Remove Agent Voice** button that
takes the engine, the service and the widget off in one go.

The engine installs into `~/.local/share/agentvoice/app` rather than
running from the plugin directory, because `plugin remove` is an `rm -rf`
and would otherwise delete the code a running service is executing --
and the uninstaller with it, leaving no way to finish. Use `--dev` to
link a checkout there instead of copying it.

### Removing it

The button on the settings' About page is the whole thing. By hand:

```bash
~/.local/share/agentvoice/app/install.sh --uninstall
omarchy plugin remove duaneoca.agentvoice
```

The uninstall deliberately leaves your voice behind -- trained verifiers
and the recordings they were built from are twenty-five clips each and
cannot be regenerated by downloading anything. It also leaves the login
keyring alone, since the API keys in it were never ours, and Whisper's
model cache under `~/.cache/huggingface`, which other things share. All
three are named on the way out, with the commands to remove them, so the
choice is yours rather than the script's.

### A wake word of your own

openWakeWord ships four phrases. For anything else, train one --
[LiveKit's trainer](https://livekit.com/blog/livekit-wakeword) generates
its own synthetic speech, so there is nothing to record, and exports ONNX
that openWakeWord loads unchanged. Take the `.onnx`, not the `.tflite`:
this pins openwakeword 0.4.0, the last release that is ONNX-only, because
0.5+ depend on tflite-runtime which publishes no wheel past cp311.

```bash
cp hey_claude.onnx ~/.local/share/agentvoice/wakewords/
```

That is the whole install. The phrase appears in the settings dropdown,
named after the file, and the daemon picks it up without a restart.

Two things worth knowing. The filename is the model's key, and a verifier
is bound to it exactly -- rename the file later and it fails at runtime
saying only "some were not matched with a base model". And the detection
threshold is tuned for whichever phrase it was set on, so measure the new
one with `agentvoice monitor`: say the phrase, then say something that
rhymes with it, and put the threshold between the two peaks.

### Tuning a wake word that misses

Listening → Advanced holds every wake setting that was tuned by hand: each
engine's threshold, the second check and its burst window (300 to 2600ms),
the short-name boost for names of three sounds or fewer, and "also sounds
like" per name word: other readings for sherpa-onnx, written as words it
knows (`thea`) or as phones (`TH IY1 AH0`). Each has a reset.

**Test my wake word** (or `agentvoice wake-test start`) counts wakes
instead of answering them, for ten wakes or 90 seconds. Say the name alone
with a pause after each, then read off how many tries woke it, which path
caught each one (spotter or second check), and the near misses the engines
turned down. Only reasons are shown, never what was said.

### A gate that follows the room

The microphone gate decides which frames are you talking, which is what ends
your turn. A fixed number suits one room: a fan coming on puts the noise above
it and a turn never ends until its 30-second ceiling, while a quiet evening
leaves it far above the floor and a soft word is cut off. **Gate follows the
room** (Listening → Microphone, off by default) makes the gate the room's
noise floor plus a margin, and shows both live.

It learns only from frames that cannot be you talking to it: the wake phase,
never a capture, never while it speaks. The floor is the median of the last
30 seconds of those, so a wake word now and then does not move it, and a TV
or music counts as the room it is. It rises at 0.5 dB a second and falls at
3, never goes below -55 or above -25 dBFS, and the fixed gate holds until it
has heard three seconds of the room. See FINDINGS §27 for six synthetic rooms
against the fixed gate.

## Principles

1. **Baseline, not bolted on.** Installs like any Omarchy extension:
   Quickshell plugin, Hyprland binds, systemd user service, config in
   ~/.config/agentvoice. Feels native to the desktop.
2. **Agent agnostic.** Follows `omarchy default agent`, so switching
   agents at the desktop switches the voice too. The voice layer never
   cares who is answering -- though the guarantees are not yet even:
   Claude Code, Codex, Gemini and Antigravity have answered live turns,
   the nine sharing the CLI adapter have not, and only Claude Code can
   raise a permission prompt.
3. **You own the mic.** Nothing listens unless you've enabled it, and
   the state is always visible. Linux has no OS level mic gate, so
   that guarantee is ours to build. That consent is per session: the
   service is started, never enabled, so a reboot or a logout leaves it
   off and the switch back at the beginning. Turning it on is one click
   and deliberately not one you make once.

   A locked screen closes the microphone, and that is not a setting.
   A machine that still answers a wake word behind a lock screen undoes
   every permission decision here by letting whoever walks up to the
   desk talk to your agent, so there is nothing to switch off. Unlocking
   restores what you had asked for and nothing else: if you had the mic
   off before the lock, it is still off afterwards. `agentvoice locked`
   answers it from a script, and the bar reads CLOSED WHILE LOCKED.
4. **Local first.** Wake word, STT, and TTS run on device. Only the
   agent call leaves the machine, if your agent does.
5. **Old hardware is the target, not the edge case.** Benchmarked on a
   2014 MacBook Pro, CPU only. If it needs a GPU it does not ship.

## Where Voxtype fits

An earlier draft of this file said agentvoice would drive Voxtype for
transcription and never open the microphone itself. That turned out not
to be possible, and it is worth writing down why, because the idea is an
obvious one to have twice.

Voxtype's running daemon exposes `record start|stop|toggle|cancel`, and
those operate on *its* microphone and type the result into the focused
window. There is no "transcribe this buffer" on the socket. The one
entry point that takes audio we already hold, `voxtype transcribe
<file>`, is a separate process that reloads the model on every call --
measured at 2.2s against ~320ms for an in-process model. And its capture
would only begin after the wake word had already been spoken, which is
the wrong moment.

So **agentvoice owns the whole input path** for wake word mode: capture,
wake word, endpointing, transcription. What it takes from Voxtype is its
shape, not its code -- a small state file the bar watches, a CLI of plain
verbs, models under XDG data.

**They coexist rather than compose.** F9 remains Voxtype's dictation and
is untouched; agentvoice listens for a phrase instead. Both want the same
microphone, which is a real constraint rather than a theoretical one:
running a wake word and holding F9 at the same time is asking one device
for two things.

## Input modes

1. **Wake word.** Say the trigger phrase, talk, get a spoken answer.
   Stays in conversation mode for a few seconds after each reply.
   Ours to build: Voxtype is push to talk only.
2. **Push to talk.** Hold F8, speak, release. Skips the wake word
   entirely, which makes it the reliable path when the room is noisy or
   the wake word is being stubborn. Distinct from Voxtype's F9, which
   dictates into the focused window -- a different job.
3. **Mute.** Release the microphone without stopping anything. Three
   ways, and they are the same action: click the microphone icon in the
   panel, right click (two finger click) the bar icon, or press
   Super+Alt+Space. The panel then reads MICROPHONE OFF and says how to
   start listening again. See *Mute, not stop* below for why this is the
   control you want rather than the switch.
4. **Interrupt.** While it is working -- thinking, or running tools with
   nothing being said -- say the wake word: it stops, chimes, and whatever
   you say next is the new request ("computer, actually make it Tuesday").
   Ordinary talk does not stop it then; you may be talking to someone else.
   While it is speaking on a headset, just talk over it: it stops, and what
   you say is your next request, with no wake word. Through speakers, press
   F8 while it is replying, or Super+Ctrl+Space, or the stop button in the
   panel -- voice cannot work over the reply there, see below.
5. **Goodbye.** In a conversation, say "goodbye" (or "bye", "see you
   later", "okay thanks, goodbye") and it stops listening for a follow-up
   and goes back to waiting for the wake word. "Stop", "cancel that" and
   "never mind" do the same. Only the whole sentence counts, so "write a
   goodbye email" is still sent.
6. **Full stop.** Say "full stop" (or "stop everything", "everybody stop")
   and every agent stops at once -- each one's turn, its voice and its
   follow-up window -- even if you said it to just one of them. The
   microphone stays on, waiting for the wake word. While an agent is
   working, say the wake word first: "computer, full stop".

### Knowing where it is without looking

Three short sounds, synthesised at startup and played from PortAudio's own
thread so none of them holds the loop (`daemon/chimes.py`, **Sounds for
listening, heard and done**):

  two rising notes    the wake word landed; go ahead
  one soft note       it heard the end of what you said; the agent is on it
  a three-note chime  a task that ran 15 seconds or more has finished

Push-to-talk gets no opening sound -- the key is the signal, and you are
already talking. While a chime sounds, the microphone keeps recording but
nothing it hears counts as speech: making it deaf instead dropped the whole
frame after the wake word, and with it the first word of anyone who did not
pause.

A long task says what it is about to do. The agent is asked for one sentence
before its first tool call and one at the end, and the reply is spoken the
moment a tool starts rather than after it finishes -- a sentence needs the
whitespace that follows it, and before this, "Let me check the logs." waited
for text that only arrived once the tool was done. Asked for a sentence
before *every* tool call, Haiku obliged; with a desktop-control loop making a
hundred of them, speech fell further behind the work with each, so the
instruction says once.

### Reading it back

The readout that appears while it works has two sizes (Display & privacy →
**Readout size**). **Locked**, the default, keeps it one size from turn to
turn: two fixed lines, the agent's last answer (dim, with an accent bar) and
what is being said now (bright), each cut short with an ellipsis when it is
long. Nothing appears or disappears, so neither the readout nor the popup's
last-heard lines move while you talk. **Dynamic** sizes it to what it is
showing: it widens to fit, up to 40% of the screen; grows taller, up to 60%;
and past that it scrolls, pinned to the newest sentence as it is spoken
unless you scroll back to reread. Either way, hovering keeps it open and
clicking it opens the whole conversation.

The last answer stays on screen while you reply to it (**Keep the last
answer on screen while I talk**). It clears, together with what you said,
when the screen locks, when you talk to another agent or switch chats, and
after ten minutes with nothing new. The readout can sit at the top or the
bottom of the screen, with small, medium or large text, and **Preview**
shows it for four seconds with sample text (`agentvoice hud-preview`).

The conversation is the session's exchanges, newest at the bottom, with a
line where each new conversation began, which turns failed or were stopped,
and how long each took to answer. The text is selectable, so a path or a
command the agent read out can be copied rather than retyped. Open it from
the panel's **Conversation** button, from the readout, or from the
**Conversation** button at the top of the settings; in a terminal,
`agentvoice history`.

It is kept beside the state file, in the runtime directory: memory only,
readable by you alone, gone when you log out, never the journal and never
the disk. **Keep this session's conversation** turns it off, and turning it
off deletes what is already kept. Clear empties it on the spot.

### Saved conversations

Off by default. Display → **Save conversations** keeps each chat on disk so
it can be browsed and picked up again later: in
`~/.local/share/agentvoice/chats/`, one file per chat, readable by you
alone. The session view above stays memory-only either way. **Keep saved
chats** chooses how long: forever (the default, since you asked to keep
them), 90 or 30 days since a chat was last used, or the last 100. Pinned
chats are always kept. Uninstalling leaves them and says where they are.

A chat is everything one agent said in one conversation. It starts when the
agent starts a new session and is titled from the first request. With saving
on, the conversation view gets a list beside it: this session first, then
Pinned, Today, This week and Older, with a search box and an agent filter.
Open a chat for **Continue**, **Rename**, **Pin**, **Export to Markdown**
(into `~/Documents`) and **Delete**. "In use" marks the chat each agent is
in right now.

**Continue** makes it that agent's current chat. Claude Code takes the
session back with `--resume` when it is the same program in the same
project folder. Anything else (another program, another folder, a backend
that keeps no session) gets the chat's words sent once, ahead of your next
request, which costs tokens, and the view says so.

By voice: "Theo, new chat" starts afresh, and "Theo, continue the chat
about the HUD" finds that agent's chat by its title and words and answers
"Continuing *HUD sizing*. Go ahead." When two chats match about equally it
names both and asks for a few more words rather than guessing. Both have to
be the whole sentence, so a request that only mentions a chat goes to the
agent as usual. In a terminal: `agentvoice chats` lists them, and `show`,
`rename`, `pin`, `delete`, `export`, `continue` and `new` do the rest.

"Allow all in this chat" still ends when the service restarts, including
for a chat continued afterwards.

While you talk, Voice → **Live transcript** can show what is heard so far.
**Accurate** shows Vosk's rough text first and replaces each part with
Whisper's at every pause you leave, so by the time you stop, what is on
screen is what will be sent. Whisper's text never falls back to Vosk's for
a part it has already read (FINDINGS §27).

**Talk while it works** (Conversation page, off by default) fills the
silence of a long turn with short sentences about what the agent is
actually doing: "I'm running the tests.", "My helper has looked through
three files and searched the code once." Each one comes from a tool the
agent really ran, through a fixed table (`daemon/narration.py`), with no
model writing them. **Brief** names the stage; **Detailed** also names
files, searches and web pages. It waits for seven seconds of quiet
(adjustable), then at least 10, 15, then 25 seconds between sentences. It
only speaks while a tool is running, never repeats itself, and gives way at
the next word break when the agent starts talking. Another agent's reply
always comes first. A secret file is "a config file", and a command line is
never read out. Only Claude Code and Codex report their tools; the others
stay quiet. Each agent's card can choose its own level. Replayed against 31
recorded turns, it spoke in 8 of them (FINDINGS §29).

**Open mic.** Say "keep listening" (or "let's keep talking", or use the
popup's **Open mic** tile) and it stops needing the wake word. It stays
with the agent you said it to; say another agent's name and the open mic
goes to that agent. "Stop listening", "goodbye", "full stop", the tile, a
mute or a lock close it. So does ten minutes with nothing said
(Conversation → Open mic → Closes after). While it is open, the bar icon
is in the theme's accent colour and the readout says "OPEN MIC · THEO ·
8 MIN LEFT". With **Only answer if it's meant for you** on (the default),
each thing it hears goes to the agent with a note asking it to reply SKIP
if it was said to somebody else or came from a television. A SKIP is
never spoken or saved. That costs one agent turn for everything heard, so
it is safer, not free. **Open the mic after every wake** makes every wake
start one.

**Commands inside a sentence.** A command does not have to be all you say.
With Conversation → Spoken commands → **Commands inside a sentence** at
*Start or end* (the default), "Take notes, and keep listening" opens the mic
and sends "Take notes"; "Remind me at five, and stop listening" closes it
after the reminder is set; "New chat. What's the weather in Paris?" starts a
new chat with that question; "Email Sarah the notes, goodbye" sends the
request and then waits for the wake word. *Own clause* also takes "keep
listening" mid-sentence: "Take notes, and keep listening, because I might
pause." *Alone* is how it was before. A command that fires inside a sentence
says so once ("Open mic on.", "New chat.") and the rest goes to the agent
as your request; "no" or "cancel that" straight after undoes an open-mic
switch. It never fires with something after the command ("stop listening to
that song", "keep listening to me"), after "don't", in quoted or reported
speech ("he said, keep listening"), as a question ("keep listening?"), when
two commands are in one sentence, in a typed message, while something else
is recording, on the agent's own voice heard back, or while the screen is
locked. Inside a sentence only the forms that are plainly instructions
count: "keep listening", "open the mic", "stop listening", "turn the mic
off", not "open mic" or "mic off", which are as often nouns ("camera on,
mic off"). After "…, stop listening" it listens for three seconds for "no"
and nothing else. Stop, full stop, take over and moving to a terminal still
work only said on their own. `agentvoice commands` lists every phrase, where it counts
and what it says, with each agent's wake phrase (`--json` for scripts).

**Move this to a terminal.** Say "Theo, move this to a terminal" and the
conversation opens in a terminal, in the agent's project folder, with
`claude --resume <session>` (Codex: `codex resume`), so typing carries it
on with everything said so far. Voice stays out of that chat while the
terminal is open. Asking that agent something then gets "That chat is open
in a terminal. Say new chat to start another one, or close the terminal
first." Once the terminal is closed, the next spoken turn resumes the chat,
including what was typed. Gemini, Antigravity, Copilot and endpoints cannot
resume a chat elsewhere and say so. A saved chat notes when it went on in a
terminal.

A failed turn says why: "Claude has hit its usage limit. It resets at
7 PM.", "Claude needs you to sign in again.", "Claude could not reach its
service." The error text itself is still never said or logged, because a CLI
that rejects its input often quotes it back. It is *classified* into a fixed
list (`daemon/failure.py`), and only the name of the kind reaches the journal
-- `agent error: limit`. A conversation that has grown too long, or that the
CLI no longer has, is dropped, since every later turn would fail the same way.

These binds. `install.sh` offers to add them and never overwrites a key
that is already bound; it backs the file up first and puts it back if
Hyprland rejects the result. They go in between markers, so `--uninstall`
takes out exactly what was put in and leaves anything you wrote yourself
alone. Say no and it prints them for you to paste, because
`~/.config/hypr/bindings.lua` is yours:

  F8 (hold)            talk to the agent; a press mid-reply stops it
  F9 (hold)            Voxtype dictation, untouched
  Super+Alt+Space      release or re-engage the mic
  Super+Ctrl+Space     stop talking, keep listening

Super+Space is Omarchy's application launcher and stays that way.

### More than one agent

Settings → **Agents** → **Add an agent** adds agents beside the main one,
up to eight. Each agent is one line there (its state, name, wake phrase,
program and model, effort, voice and speed, and permission level), and
opens into cards: Identity, Permissions, Voice, Tools, Collaboration &
notes, and Agent, plus Endpoint for an agent that runs on one.
Each is woken by its own name and has its own program, model, effort,
voice, permission level and folder, and its own conversation. Say
"computer" for the main agent and "jarvis" for the one called jarvis.

Settings → **Agent details** holds what each agent is told, one tab per
agent: its role (what the other agents are told about it), its personality
and its standing instructions. Each box has a meter counting the characters
the agent is actually told, against its budget (300, 1500 and 2000), and
offers a few starters while it is empty. The tone, length and formality
chips write one line at the top of the personality, `Traits: warm, brief,
casual.`, and never touch what you typed below it. **▶ Try it** runs one
short turn on the agent's program, with no tools and nothing saved, and
says its first sentence aloud in the agent's voice, using what is in the
boxes at that moment, saved or not. It is refused, with the reason, while
the screen is locked, while an agent is busy, or within 10 seconds of the
last try.

They can work at the same time: while one is thinking or running tools the
microphone keeps listening, so you can give a second agent something to do
before the first has answered. Speaking is still one at a time, because
there is one room. Nothing is listened to while an agent talks, a reply
that has started keeps the floor until it goes quiet for a moment, so two
answers are never interleaved, and no reply starts while you are talking to
any of them.

Start a sentence with a name to talk to that agent from anywhere: "Jarvis,
what's on my calendar?" inside another agent's follow-up window goes to
jarvis. Saying the name of an agent that is working stops it, as the wake
word always did, and leaves the others alone. "Jarvis, stop" stops jarvis.
The panel's Stop button and the interrupt key stop everyone. Push-to-talk
goes to whoever you spoke to last.

A name has to be a word the wake engine knows. Vosk is asked, and a name it
cannot hear is refused with the reason in the settings, the same reason
"hey omarchy" is not a wake phrase. sherpa-onnx is asked the same way,
through its phone lexicon. openWakeWord hears only its own phrase, so extra
agents need Vosk or sherpa-onnx.

An extra agent's permission level and folder are its own. Trusting the main
agent does not trust the others, and the permission hook is told which
agent it is guarding. One it cannot find in the settings, or one whose
program has changed since, is asked about rather than allowed.

Every agent, the main one included, has a **Name** apart from its **wake
phrase**. The name is any text, and it is what the readout, the popup, the
permission card, the conversation and the Agents panel call it. The wake
phrase is what you say, one to three words the engine can hear. Leave the
name empty and it is the wake phrase, capitalised. Behind both is an id
that neither changes, and grants, the permission hook and the Agents panel
know the agent by that id. So renaming an agent or giving it a new wake
phrase keeps its conversation and its "allow all in this chat". An agent
saved before names existed gets its old wake word as its id, which is what
everything already called it, so nothing moves. Two agents may share a
name, but never a wake phrase.

### Agents working together, and the Crew map

Claude Code and Codex agents can ask each other a question, give each other
a task, pass one the conversation or leave one a message, and you can pass a
conversation yourself ("pass this to Sora", or **Send to another agent**).
Each agent's **Collaboration** setting says how you hear about what it
starts: not at all (off), asking you first, announced out loud with a moment
to say stop, or quietly.

Settings → **Crew map** says who may do which of those to whom. An agent
reaches another only along a link there that allows it, and a link goes one
way: Theo → Sora lets Theo give Sora a task and nothing else. With no links
nobody can reach anybody, which is how it starts on an upgrade; **Link
everyone as before** puts back every agent able to do everything with every
other, after a confirm. A link can also **Ask me first**, which puts the
approval card up for every call over it whatever the caller's own setting
says. That card is answered only from this screen, but an agent at Trust
everything could run commands to answer its own, so for a Trusted agent it
is advisory.

**Quarantine** holds an agent apart: it starts nothing, other agents may
only ask it a question or give it a task, a task reaches it as the brief
alone (at most 1000 characters, never the chat), what it answers comes back
marked as from a quarantined agent, and it writes no communal note.
Quarantining it ends its sessions and the chats shared with it; releasing it
gives none of that back. A pass you start yourself needs no link, but never
goes into quarantine.

The page opens on a **map**: each agent a box, each link a line with an
arrow at the agent it reaches and a label saying what it carries (A ask, D
give a task, M message, P pass, ? asks you first). Drag from an agent's dot
onto another to link them (the new line allows asking); click a line's label
to change what it allows, add the reverse or delete it; click an agent to
see whom it reaches. Drag an agent into the red zone to quarantine it (after
a confirm that says what it loses) and out again to release it. Boxes stay
where you put them; that is kept on this computer only and means nothing to
the daemon. **Table** shows the same list as rows. Either way, nothing is
saved until the daemon's own rules have checked it.

The daemon enforces all of this, reading the list fresh for every call and
again before queued work starts and before an answer is handed back. A list
that cannot be read refuses every call an agent starts, and says so on
screen. The page is only an editor of the list, and says when it was changed
outside Settings.

### Endpoints for any agent

An extra agent can run on an OpenAI-compatible endpoint of its own: choose
**Endpoint** as its program. The main agent's **Runs on** has the same
editor. Each endpoint has its own address, model, key, timeout and number
of turns remembered.

- **Presets** fill in the address for Ollama, OpenAI, Groq and xAI, the four
  that have answered a real turn here (FINDINGS §14). LM Studio, llama.cpp's
  server, vLLM, OpenRouter and Hermes work too, by typing their address.
- **The address is forgiving.** `localhost:11434` becomes
  `http://localhost:11434/v1`, a pasted `/chat/completions` is cut back,
  and a public host without a scheme gets `https://`. The page shows the
  address that will actually be used.
- **List models** asks the endpoint (`/v1/models`, or Ollama's own list).
  **Test connection** sends one tiny request and says how long the first
  word took, or what is wrong in plain words: "Ollama isn't running", "it
  wants an API key", "model not pulled: run ollama pull qwen3:4b".
- **Keys** are saved per host in `~/.config/agentvoice/endpoint-keys.json`
  (yours alone to read), never in the settings, and shown masked. A key in
  the login keyring for that host still wins.
- **Thinking is never spoken.** A reasoning model's `<think>…</think>`, or
  the separate reasoning field some servers send, is taken out before
  anything is said and shown greyed, folded, in the conversation view.

### On the desktop

Settings → **Communal** → **Tools**, for every agent. An agent's own
switches are on **Agent details** → **Tools & skills**, where any of these
can be turned on or off for that agent alone; its **Tools** card on the
Agents page says which it has and whether that is its own choice or the
one for every agent.

**Desktop tools** (off by default) gives Claude Code agents an MCP server
of Agent Voice's own (`daemon/desktop_mcp.py`). With it they can open an
app by its launcher name, focus, move and close windows, switch workspace,
open a project (a terminal and the editor in its folder, and the browser),
control media and volume, notify, and read and write the clipboard. They
can also take a screenshot, lock the screen, or suspend. Each tool goes
through the agent's permission level: listing windows is free; a change,
or reading the clipboard, is asked about below Trusted; a screenshot is
asked about every time, at every level. Locking and suspending work only
when the request you just made says so.

With desktop tools on, agents can also open a file in your editor at a
line (VS Code-style editors take `--goto`; terminal editors get `+line`),
and open a side-by-side diff of what changed in a git folder since the last
commit. Diffs need a VS Code-style editor. On Hyprland with a Lua config
(Omarchy 4.5), window commands are sent in Lua, with the old form as a
fallback.

**Browser** (off by default) gives Claude Code agents Claude in Chrome, which
is your own browser, signed in as you. Reading pages follows the agent's
level. A click, key, typed text or form fill whose own summary says it
sends, buys, posts, books, deletes or the like is asked about at every
level, Trusted and "allow all in this chat" included. So is running code
in a page, uploading a file, or a click that does not say what it does.
The question is said out loud ("Theo is asking first: places the order.
Answer on screen.") as well as shown. A trusted agent with the browser
gets a hook on the browser's tools only, so nothing else is slowed.

**Omarchy skill** (on) tells agents the exact `omarchy` commands this
machine has, and what each keybinding does. It is built at install from
`omarchy commands --json` and `hyprctl binds -j`, and built again when
Omarchy updates. Claude Code loads it as a skill for the voice session
only, and nothing is written into `~/.claude`. Codex, Gemini, Antigravity
and Copilot get a shorter list in their instructions. With it, Claude
named three version-specific commands exactly; without it, one
(FINDINGS §31).

### Tools found on this machine

Agent Voice looks for the MCP servers your coding agents are set up with --
in Claude Code's own settings (`~/.claude.json`, a project's `.mcp.json`,
enabled plugins) and Codex's `~/.codex/config.toml` -- and for command-line
tools that reach an account or a service (`gh`, `aws`, `docker`, `stripe`
and the like, plus any you add by name). It reads those files and never
starts anything to find out. Each one is a switch on **Agent details** →
**Tools & skills** (for one agent) and **Communal** → **Tools** (for
every agent); an agent's own off always wins.

**Everything found is off until you switch it on.** Before this, a Claude
Code agent quietly loaded every MCP server in your own settings, and a
project's `.mcp.json` without asking; now Claude Code is started with
`--strict-mcp-config` and only the servers switched on for that agent, and
Codex with the rest of its config's servers switched off. The first time
you open an agent's Tools & skills tab it lists what it had before and is
now off, each with **Turn on**.

Turning one on shows what it runs, where it is defined and who gets it,
and asks. A switch approves that definition: if the server's command,
arguments or environment change later, it is off again and says "changed
since you turned it on". A server's definition (it can carry an API key)
goes to Claude Code in a private file, never on the command line, and is
never logged.

What "on" means, as measured with real turns (`tests/fixtures/tools/`):
an MCP server below Trusted asks before each call on Claude Code, and is
refused by Codex itself (it cannot ask); at Trusted it runs without asking,
and the switch says so. A command-line tool is **told, not enforced**: the
agent is told which it may use and which are switched off, and Claude Code
also refuses the plain command for one that is off -- but `sh -c` gets past
that, so the page never calls it enforced. An agent with a found server on
has its notes and answers marked as possibly holding outside text, like
the browser. Gemini, Antigravity and Copilot still start the MCP servers in
their own settings; their tab says so.

### Skills on this machine

Agent Details → **Tools & skills** shows every skill on the machine as a
card in its owner's lane: one lane per agent (its own skills, and the ones
its program finds by itself), **Communal**, and **Unused**. Unfold a card
for its description, where it lives, its size, any problem, and who gets it.

Claude Code and Codex find skills by themselves -- Claude Code in
`~/.claude/skills`, your claude.ai account's synced skills and enabled
plugins; Codex in `~/.codex/skills` and `~/.agents/skills` -- and every
agent on those programs has always seen them. Nothing changes about that
by default. What is new is a **switch on every card an agent would get**,
its own, the communal ones and those: off takes the skill out of what
that agent's program offers it (Claude Code's own skill switch, which its
Skill tool then refuses; Codex's `skills.config`), and out of what Agent
Voice gives it. The file itself is not touched, and an agent that can read
files can still open it, so the page never calls that hiding. An Agent
Voice skill beats one the program finds of the same name, so an agent never
has two.

**Unused** holds skills found outside Agent Voice that no agent gets. Give
one to an agent, or to Communal, and it gets a **checked copy** -- no links
inside, no hooks, within the size limits -- after a question that says who
gets it. Agent Voice never edits, moves or deletes a skill it did not make.

**Moving a skill.** Drag a card from one lane to another to move it, or
hold Ctrl to copy it; every card also has a **Move to…** button (Menu or
Ctrl+M from the keyboard) that does both. Communal → Skills has the same
lanes. Moving a skill into Communal asks first ("every agent will get this
skill"), and so does moving one out of a quarantined agent. A name already
taken where it would land is refused, with the reason. **Undo** is offered
for ten seconds, and works only while neither side has changed since, so it
never loses an edit; from a terminal, `agentvoice skills history` and
`agentvoice skills undo OP` do the same at any time. A move is staged and
published in one step, and one cut short by a crash is finished or put back
before any agent sees either side. A skill found outside Agent Voice is
only ever copied in, never moved.

**Notes are topics.** Each note is one subject (a shopping list, the garden,
how the house runs), and agents are told to add to a topic's note rather than
start another. The Notes tab shows each as a card with its topic and its first
line, in its owner's lane: this agent's first, then every other agent's and
Communal's (Communal → Notes shows the same lanes). Drag a card to another lane
to move it, hold Ctrl to copy it, or use its **Move to…**; the note takes its
past versions, who wrote it, its lock and its "may contain text from web pages"
mark with it. Moving one into Communal, out of a quarantined agent, or a note
with that web mark asks first, and says that its past versions go too. **Undo**
is offered for ten seconds; `agentvoice notes history` and `agentvoice notes undo
OP` work at any time. **Combine…** merges several notes of one folder into one
topic: the first you pick is kept and the others are added under it, each with
its topic as a heading. A note combined away keeps all its past versions, and
**Earlier notes** puts it back. Agents cannot move or combine notes.

### In Omarchy's Agents panel

Each voice agent also gets a section in Omarchy's own Agents panel, the one
behind the robot icon: "Claude Code (voice)" for the main agent, "Sarah
(voice)" for one called sarah. The line on its right says what it is doing
-- *Listening for “sarah”*, *Thinking…*, *Speaking*, *Off* -- and the info
mark beside its name says what it runs on, what it may do, and how many voice
turns it has had today.

That panel draws any record it finds in `~/.local/state/omarchy/agents/usage/`,
so this changes nothing of Omarchy's: the daemon writes one
`agentvoice-<name>.json` per agent, renamed into place, at most once a second
and only when something on it changed. A new agent appears the next time the
panel is opened, which is when it looks for new records. Stopping the service
leaves the sections saying *Off*; removing an agent removes its section; the
uninstaller removes them all.

They add nothing to the panel's token and prompt totals. A voice turn runs the
agent's own CLI, and that CLI's usage is already counted under its own
section; counting it again here would show every spoken prompt twice. Turn the
sections off under Settings → **Display** → **Show each voice agent there**,
or hide one with Omarchy's own per-agent switch.

### Mute, not stop

The switch in the panel and the microphone icon beside it do different
things, and reaching for the wrong one is expensive.

The switch starts and stops the **service**. Stopping it unloads
everything: the wake engine, Whisper, and the Piper voice, roughly 600MB
resident. Starting it again reloads all of that and re-reads the config,
which is three to four seconds on this machine before it can hear a word
-- measured from `Started` to `listening for` in the journal. It is the
right control for "I am done for now", and it is the per-session consent
gate: the service is started and never enabled, so a reboot leaves voice
off until you ask for it again.

Mute releases the **microphone** and leaves the service running. It is
instant, the models stay warm, and the next word you say is heard
immediately. It is the right control for "not in front of this person",
"I am about to dictate into something else", or "stop listening while I
think".

Muting also survives a screen lock correctly, which stopping does not
approximate. A lock closes the microphone on its own and unlocking
restores what you had asked for -- so if you muted before the lock, it is
still muted afterwards, and if you had not, it starts listening again.
Nothing is saved and restored around a lock, so there is no stored copy
to fall out of step with.

### Why you cannot interrupt by voice through speakers

On a headset you can, and it is on by default (**Let me interrupt by
talking on a headset**, `bargeOnHeadset`): the daemon asks PipeWire where
the sound is going, and when it is headphones or a headset it listens over
the reply. Measured on a Bluetooth headset, our own voice reached its
microphone as digital silence (bench/FINDINGS.md §21). When it hears you,
it stops speaking, stops the agent, and keeps listening: what you said over
it, from its first word, becomes the next turn. A bare "stop" is a turn
like any other "stop" and is discarded.

While nothing is playing -- the agent thinking or running a tool -- none of
this applies, so the wake word is listened for on speakers and headsets
alike, and it stops the turn. Only the wake word: talking during that
phase used to wait in the queue and stop the reply the moment it started.

Through speakers, the obvious design is to say "stop" over the reply. Measured on this
hardware -- one laptop microphone about a foot from the speaker it is
listening to, at a normal listening volume -- that does not work:

  wake word detected in a quiet room       19/20
  wake word detected over our own reply     5/20

The reason is simple once measured: our own playback arrives at the
microphone at the same level as your voice. Signal to noise is +1.2 dB,
and the detector needs about +24 dB to be reliable. That is a ~23 dB
deficit, and a dedicated "interrupt" phrase would be swamped identically
-- the failure is acoustic masking, not vocabulary.

The detector never false-fires on our own voice: peak score 0.001 at every
volume up to 100%, against a 0.75 threshold. Listening while talking is
safe; hearing over it is not.

PipeWire's echo canceller does fix it, and completely:

  no cancellation              SNR  +1.2 dB    5/20
  module-echo-cancel, converged SNR +13.4 dB   19/20

Two conditions keep it out of the default install. Its stock settings
enable webrtc's noise suppressor and AGC, which gate the wake word into
unintelligibility (0/20) while appearing, if you only look at median
levels, to be cancelling beautifully. And the adaptive filter needs
roughly 30 seconds of continuous output to converge -- far longer than a
spoken reply -- so it is unconverged exactly when a short answer needs it.

Half duplex with an explicit interrupt is honest about *this* hardware.
Whether it is honest about yours is a property of the room, so there is a
way to find out:

  agentvoice calibrate

It speaks, measures how loudly its own voice comes back through your
microphone, then listens while you talk and reports the gap. Nine dB of
headroom or more and barge-in works; here it is negative, because the
microphone sits beside the speaker.

The mechanism, when it does work, is not wake-word detection through the
bleed -- that needs about 24 dB and was measured at 5/20. It is the
question telephony has always asked: is that speech, and is it louder
than the echo? A voice activity detector answers the first half and an
energy gate calibrated to our own output answers the second, with only
sub-gate frames updating the estimate so your voice can never raise the
bar it has to clear. Detection measured 8/10 here -- the trouble is that
every setting which hears the user also fires on us.

The approach is [Atzingen/hey-jarvis](https://github.com/Atzingen/hey-jarvis)'s,
found while checking whether this duplicated existing work. It does. Its
defaults floor the gate at -38.4 dBFS, which is below the bleed measured
here, so out of the box it interrupts itself within a second -- which is
a fact about this laptop, not about their code.

## Architecture

**Voice daemon** (Python, systemd user service)
Owns the microphone and everything done to what comes off it: wake word,
endpointing, transcription, conversation state, speech. Publishes what it
is doing to a state file the bar widget watches, and takes commands
through the `agentvoice` CLI (`start|stop|toggle|mic|status`), which
signals it rather than opening a socket -- the same shape Voxtype uses.

**Audio path**
100ms frames from PipeWire. Every frame is measured and dropped below the
gate, so nothing quieter than the room reaches the wake word. After the
wake word fires, the same frames feed both an endpointer and a buffer;
when a pause ends the turn, the buffer goes to Whisper in one piece.
While the machine is speaking the microphone is deaf, and the queue is
drained afterwards, because one microphone beside one speaker cannot
win -- see *Known risks*.

**Backend adapters**
One contract: take text plus a session ID, stream text back. Which agent
answers follows `omarchy default agent`, unless an endpoint URL is set,
which wins because the desktop has no entry for "the model on my other
machine". That rule is reasonable and surprising in equal measure --
choosing an agent in Omarchy's settings and having nothing change looks
exactly like a broken setting -- so the panel names what is being
overridden (`endpoint · … · instead of claude`) and clearing both
endpoint boxes hands control back.

Eight have answered a live turn. The columns that decide how it feels to
talk to are not the ones that decide how capable it is:

| backend | reached by | remembers | tools | a two-sentence answer |
|---|---|---|---|---|
| Claude Code | CLI, headless | yes | yes | — |
| Codex | CLI, `exec --json` | yes | yes | 2.8s |
| Antigravity (`agy`) | CLI, `-p --output-format json` | yes | yes | 12.2s |
| Groq | endpoint | yes | no | 0.19s |
| OpenAI | endpoint | yes | no | 1.9s |
| xAI Grok | endpoint | yes | no | 3.2-4.6s |
| Ollama, LM Studio, vLLM | endpoint | yes | no | 7.6s on a LAN 4B |
| **Gemini** | CLI | **no** | yes | — |
| Copilot | CLI, piped stdin | **no** | yes | — |

**Two of these act here, and one acts somewhere else.** Claude Code,
Codex, Antigravity and Gemini are started by this daemon, in a directory
it chooses, under flags it passes -- so the project and permission
settings mean something, and what they protect is this machine. An
endpoint is a URL. agentvoice gives it no flags, no hook and no sandbox,
and cannot see what is behind it.

Usually that is a chat completion which can do nothing at all. Sometimes
it is an agent: Hermes speaks the same wire format, and its own
documentation calls its bearer token equivalent to a root password --
terminal and filesystem on the Hermes host. Asked for the hostname it was
running on, it answered with it.

The difference is not how dangerous it is, it is *where*. Nothing this
machine holds is at risk from Hermes; the Mac mini it runs on is. Which
also means the project directory and permission level do not apply --
they govern an agent started here, and reach nothing over there, so the
panel drops them and the settings screen says why. Restrain a remote
agent where it runs.

Tick **This endpoint is an agent** when the endpoint can act. agentvoice
cannot tell from the URL, so until you say, it claims nothing about the
far end -- only that it offers no tools itself.

**Remembering is three different mechanisms, and one absence.** Claude
Code, Codex and Antigravity each keep the conversation themselves and
hand back a handle -- `--resume`, a `thread_id`, `--conversation`.
Claude Code also keeps its *process*: one is started the moment the wake
word fires, while you are still talking, takes each turn on stdin as
stream-json, and is let go after five idle minutes or any stop. Starting one
per turn cost about a second before the first word, every time; waiting, it
holds ~230MB. The
endpoint keeps no server-side session at all, so the transcript is ours:
it is replayed up the wire every turn, capped at eight turns, and every
replayed turn is re-read and re-billed. Gemini's headless mode is
one-shot and returns no handle of any kind.

That last row is the one to know about, because it fails quietly.
Conversation mode still opens its window after a Gemini reply, still
listens, still answers -- and every turn starts from nothing. Ask "what
did you mean by that?" and you get an answer to a question it has never
seen. The same is true of Copilot, which shares the plain-stdout adapter.

**There used to be ten on that adapter.** Nine were removed in October 2026
rather than shipped: every one of them passed the spoken prompt as a
command-line argument, where `/proc/<pid>/cmdline` makes it readable by any
other local account for as long as the turn runs. Moving them to stdin meant
knowing which of them reads a prompt there, and asking each binary gave no
answer -- two dropped into an interactive interface, one crashed, five
stopped at authentication or configuration first, and one turned out to be a
stub rather than an install. A prompt written to a channel a CLI is not
reading is a turn that hangs, so the choice was between guessing on nine
backends and offering none of them. None had ever answered a live turn. Every
backend listed above hands the prompt over privately: on stdin for the CLIs,
in an HTTPS body for the endpoints.

Two smaller things that follow from the mechanism. An interrupted
endpoint turn never enters the history, because the history is written
when the stream ends -- so the machine forgets its own half of an
exchange you cut short. And the follow-up window is shortened by
`echoTailMs`, which is counted from the same moment, so a 4s window with
a 350ms echo tail is really 3.65s.

Switching agent or project drops the session id, deliberately: a handle
from one project resumes the wrong conversation in another.

**Project and permissions**
The agent works in one directory, and what it may do is a property of
that directory and of the agent -- shown together on the panel so you can
see before you speak what you are about to affect and how much it can do
without asking. Empty means your home directory, which is what a bare
`claude` does.

  ask       every change is prompted
  edits     files inside the project may be edited without asking;
            commands, web fetches and anything outside it still prompt
  trusted   nothing is asked

**The level is per agent, and absence is never permission.** Trust is a
judgement about one program's capabilities, and those differ enormously:
Claude Code can be stopped mid-call by a hook we answer, Codex cannot be
stopped at all. A single global level meant that trusting Claude Code
silently handed the same trust to whatever `omarchy default agent` was
switched to next. Levels are stored per agent, an agent nobody has
decided about reads as `ask`, and switching agents at the desktop is
picked up live rather than at the next restart.

Each backend offers only the levels it can honour, and the panel names
what is actually in force -- `claude · edits here · commands ask`, or
`codex · read-only (codex cannot ask)`. `edits` needs somewhere to put
the question or a flag that means it, so today only Claude Code has it.
Offering three levels where one is a lie is how a screen ends up
promising a guarantee that is not running.

`edits` is the level that stops you approving reflexively: editing files
is frequent and legible, running shell commands is rare and dangerous, so
they are separated. Bash is never path-scoped at any level -- `cd /; rm
-rf .` carries no file path, and no prefix match makes one safe to infer.
Path rules compare fully resolved paths, so `..` and symlinks cannot walk
out of a trusted project.

Changing the project drops the session id, because `--resume` is scoped
per project in Claude Code and would otherwise resume the wrong
conversation.

A spoken sentence should not be able to edit files unchallenged. For
Claude Code, a PreToolUse hook passed through `--settings` receives each
tool call, hands it to the daemon, which summons the overlay, and waits.
The overlay shows the tool and the command verbatim with Deny,
Allow once, and a countdown; silence denies. Read-only tools are never
asked about, because a prompt on every Read would train you to say yes.

The answer goes back to the daemon over its socket, and since M7 only
the overlay can say yes. The daemon checks with the kernel which process
sent it: one the running Omarchy shell started itself, reading the
shell's own pipe, carrying the one-use code the daemon handed that card.
A yes from anywhere else, such as `agentvoice permit ID allow` typed in a
terminal or run by an agent, is refused and the question is denied. A no
is taken from anyone. A card cannot be answered while the screen is
locked, and locking the screen denies it. This stops an agent answering
its own question the easy ways. It does not stop a program running as
you that sets out to beat it: one that drops a plugin into the shell, fakes
input, or rewrites this plugin. Below Trusted an agent cannot do any of
those without asking you first. At Trusted it can, so a question put to
you about a Trusted agent's work is advisory, not a guarantee.

Not `--permission-prompt-tool`: that flag is accepted by the CLI and
does load the MCP server, but is never consulted -- tested against
2.1.278 in every permission mode. Hooks fire in all of them.

No other agent can raise a prompt from here. Adapters say so with
`guards_permissions`, and the ones that cannot are held in the safest
mode their CLI offers instead of its unattended one -- Gemini in
`--approval-mode plan`, the rest simply denied their bypass flag. That
fails closed by stalling rather than acting, which is the right
direction and a worse experience than asking.

**Desktop integration**
Quickshell plugin `duaneoca.agentvoice`, kinds `bar-widget` and
`overlay`. State icon (off, idle, listening, thinking, speaking),
click to toggle, and the hot mic indicator. The bar talks to the
daemon over IPC the way the Dictation indicator talks to Voxtype.
Omarchy 4 has no Waybar.

## Stack

Measured on the target hardware. See `bench/FINDINGS.md`.

**STT** faster-whisper `tiny.en`, in process, with a custom vocabulary
prompt. 4.9% WER against 6.5% for `base.en` with the same prompt, at
roughly half the latency. `small.en` is disqualified: nearly two seconds of
dead air on every turn.

That latency is no longer paid after you stop. The ~320ms this used to quote
was short benchmark clips; real turns in the journal ran a median of 7.6s and
1.1s of Whisper on `base.en`, all of it after the last word. Now every pause
sends what came before it to Whisper in the background, so by the time the
endpoint has waited out its silence the transcript is usually finished --
`0ms waited` in the journal. A piece shorter than three seconds is not kept
on its own; it is heard again as part of a longer one. `daemon/eager.py`.

When the words are already in and read as a finished sentence, a shorter
pause ends the turn (**Shorter pause when you sound finished**, 800ms; 0
turns it off). Trailing off with "...", or stopping on "and", "the", "to"
and the like, still waits the full pause, because being cut off is worse than
waiting.

**Custom vocabulary** is a first class component, not a tuning knob. A
fourteen word `initial_prompt` cut domain errors by 41% for 41ms.
That beat jumping two model sizes, which cost 1.8 seconds. Users edit
the term list; project names and tool names go in it.

**TTS** Piper `lessac-medium`. 22ms to first audio, RTF 0.045, which
is 22x realtime. espeak-ng is the fallback for machines that cannot
manage even that; it is robotic and costs 6ms.

**Wake word** three engines, chosen in settings, because they fail
differently.

*Vosk* (default) takes any phrase you like and costs 26MB. Its weakness
is not accuracy but the shape of the question it answers: a grammar has
to choose between the phrase and anything-else, so a phonetic neighbour
maps cleanly onto the phrase at full confidence. Measured here, `"hey
cloud"` scores **1.00** against a `"hey claude"` grammar, and `"apple
pie"` scores 0.89 against `"hey pi"`. A confidence threshold cannot fix
this; there is nothing to threshold.

*openWakeWord* has four pretrained phrases and real separation --
`"hey jarvis"` 0.996, a phonetic attack 0.898, unrelated speech 0.000 --
so 0.90 rejects the near miss and still fires. That threshold belongs to
those four; a model you train yourself needs its own, which is why the
trainer measures one rather than guessing. How much room it has depends
almost entirely on the contrast set: the same speaker and model scored a
median of 0.775 against four clips from one synthesised voice and 0.963
against twelve from three, where all 25 recordings clear 0.89.
`bench/FINDINGS.md` §15 has both sets of numbers and why the first was
misleading. It costs ~154MB, almost
none of it the detector: scipy and scikit-learn are hard imports of its
package `__init__`. Pin `openwakeword==0.4.0`; 0.5 and later depend on
`tflite-runtime`, which has no wheel past cp311.

*sherpa-onnx* keyword spotting is a 3M-parameter streaming recogniser
held to the phrases it is given. It takes the phrase and the agents'
names as text, like Vosk, by turning them into phones through its lexicon,
so nothing is trained. Unlike Vosk it scores the sound itself. On the
synthesized corpus in `bench/FINDINGS.md` §23 it caught the same 28 of 30
wakes as Vosk with 8 false wakes in 150 untuned, against Vosk's 63, and
none on ordinary sentences (Vosk: 7 of 36). Its cost is 4% of a core
against Vosk's 2%, and about 44MB resident. Like openWakeWord it is fed
every frame, not gated, and its threshold is a slider. Changing the
threshold or adding an agent opens a new stream without reloading the
model. Optional, and installed with `--sherpa`.

**Personal verifier** the only layer that knows *who* is speaking. Both
engines above are speaker independent by design, which is why a podcast
wakes them. `agentvoice-train-verifier` fits a logistic regression over
openWakeWord's embeddings from a couple of dozen clips of your voice,
against other speech and against other voices saying your phrase. It runs
only after the wake word has already fired and replaces that score.
Measured: no loss on the owner's voice, and it rejects every held-out
other-speaker clip the base model accepts. `agentvoice monitor --ab`
scores both on the same audio if you want to check your own.

**Echo cancel** not implemented. The plan is PipeWire
`module-echo-cancel`, capturing from the cancelled source node rather
than raw ALSA. Until then the microphone goes deaf while the machine
speaks, and for a configurable tail afterwards, which works but makes
barge in impossible. On the dev machine the module is not even loaded --
the only filter present is a speaker EQ.

## Open questions

1. **Does a verifier reject a real stranger?** Answered for the
   behaviour, still open on the attribution. Trained on the owner's
   voice it costs almost nothing and rejects everyone else: eleven live
   utterances fired 11/11 either way (mean 0.963 with, 0.987 without),
   while twelve held-out other-speaker clips were accepted 8/12 by the
   base model and **0/12** with the verifier -- but those speakers were
   synthetic. On 2026-10-04 a real person at the microphone said the
   phrase six times and was acknowledged **0/6**, with the owner waking
   it first try in the same session and configuration. What that does
   not separate is the verifier's own contribution: the base model was
   never run against those six utterances and they were not recorded,
   so it measures the stack as configured rather than the layer under
   test. Keeping the next stranger's attempts as wavs would settle it.
   See `bench/FINDINGS.md` §17.
2. **Streaming transcription.** Answered: worth it, and built -- not as
   overlapping chunks but by cutting at pauses, where no word can be split.
   Measured end to end, it took Whisper's 1.0-1.1s on an 8s utterance down
   to nothing waited. See *Stack* above and `bench/FINDINGS.md` §19.
3. **Moonshine and Parakeet.** Both are built for low-latency short
   utterances and both appear in Voxtype's ONNX build. Either could beat
   `tiny.en` on the metric that matters -- time after you stop talking.
4. **Microphone contention.** agentvoice holds the microphone
   continuously in wake word mode. What that does to Voxtype's F9, and
   to any other recorder, is untested.

## What it costs to run

Roughly **600MB resident** and 5% of one core, idling. The models are what
weigh: whisper `tiny.en` 323MB, openWakeWord with its scipy and sklearn
179MB, a Piper voice 48MB, the Vosk model 114MB when the engine or the
live-transcript setting needs it, or sherpa-onnx about 44MB in its place.
Only the models actually in use are
loaded, and switching engines releases the other one.

On disk it is about 750MB installed, or 900MB with openWakeWord as well;
sherpa-onnx adds about 60MB.

That is comfortable on the 2014 laptop this was built on, which has 16GB.
It is not nothing on a 4GB machine, and principle 5 says that matters.

## Known risks

1. Laptop speakers into laptop mic: false wakes, broken barge in.
   Worst case on the dev machine, which has one mic and no array.
2. Thermal throttling. The dev machine logged 13,471 throttle events
   during benchmarking, and sustained inference degraded latency 2-3x.
   A long conversation gets slower. Budget for it.
3. Microphone gain. Shipped at +12dB on the dev machine, clipping 1.46%
   of samples at a normal speaking distance. Calibrate at install.
4. **Phonetic neighbours wake the Vosk engine.** Not a tuning problem: a
   grammar scores `"hey cloud"` exactly as high as `"hey claude"`. Use
   openWakeWord, and a verifier, if anything in the room talks.
5. **The permission guard is uneven.** Only Claude Code can put a
   question on screen, through a PreToolUse hook that fires whether the
   model likes it or not. Codex, Gemini and Antigravity are held in
   their CLI's safest mode instead, so they refuse work rather than ask
   for it. Antigravity has a hook with a richer vocabulary and it cannot
   grant: in headless mode `allow` is ignored, so a hook there can
   restrict and never permit.
6. **Not every backend remembers the last thing you said.** Gemini and
   Copilot on the shared CLI adapter starts from nothing on every turn,
   and conversation mode gives no sign of it -- see *Backend adapters*.
7. **Cold stubs look installed.** Omarchy puts a mise stub on PATH for
   every agent it knows, so `command -v` finds every one of them on a machine
   with none of them. Invoking one triggers a minute-long install.
   Adapters check for a real install, not just a name on PATH.

### And the ceiling

Worth saying plainly, because the rest of this file is about things that were
fixed. What agentvoice gives an agent is a microphone and your shell. It runs
as you, with your files, your keys and your network, and the permission guard
is a speed bump against an accident or a passing stranger rather than a
sandbox. Three limits follow from the design and are not going away:

- **Bash is outside the credential list.** The names and locations under
  *Known risks* govern the file-reading tools -- Read, Grep, Glob. A shell
  command can read the same bytes, and the guard sees only "Bash" and a
  string: at `ask` or `edits` it asks, but it cannot tell you that the command
  reads a private key, and at `trusted` it does not ask at all. Parsing shell
  for credential paths is the game this project declines to play, because
  `cd /; rm -rf .` names no file either.
- **Replies are spoken out loud.** Ask for something sensitive and it comes
  out of the speakers, in a room that may have other people in it. Nothing
  filters what is said aloud.
- **The input channel is the room.** A locked screen closes the microphone, a
  personal verifier rejects other voices, and mute is a click away --- those
  narrow the opening, they do not close it. A wake word is an open
  microphone, and that is the deal.

None of that is a reason not to use it. It is a reason to choose the
permission level deliberately, to prefer `ask` or `edits` over `trusted` on a
machine that matters, and to know that "trusted --- never asks" means exactly
what it says. The licence disclaims warranty in the usual legal words; this is
the same thing in plain ones.

## Prior art (and the gap)

Voxtype: Omarchy's own dictation, local whisper.cpp, push to talk.
  Input only, types into the focused window. We coexist with it;
  driving it turned out not to be possible. See above.
voice-to-claude: local wake word dictation for Claude Code on Linux.
  Input only, no spoken replies.
tryvoice: adapter registry for Claude Code, OpenClaw, custom.
  Browser and cloud leaning, not a native desktop daemon.
talk-to-claude, VoiceMode: MCP servers driven from inside a Claude
  session. The agent runs the loop, not the desktop.
Claude Code native voice: hold to talk, and the transcription is a
  hosted service rather than a local model.

None is a desktop level, agent agnostic, speaking voice layer.
That's this.

## Build order

Done:

1. Wake word to transcript, two engines, tunable from the bar
2. Claude Code adapter: headless, streaming, session resume
3. Replies written for the ear, spoken sentence by sentence
4. Quickshell plugin, settings overlay, install script, user service
5. Personal verifier training tool, and a permission prompt for
   Claude Code
6. Push to talk on F8, and an interrupt. Barge-in by voice was measured
   and rejected rather than skipped: at a normal listening volume our
   own playback reaches the microphone as loudly as the speaker does
   and detection falls to 5/20, where reliable wake needs about +24 dB
   of headroom. Echo cancellation closes the gap but wants ~30s of
   continuous output to converge, which is longer than a reply. The
   numbers are in `bench/FINDINGS.md`.
7. A project directory the agent works in, and permission levels that
   are per agent, because trust is a judgement about one program's
   capabilities and cannot survive swapping the program.
8. Eight backends answering live turns: Claude Code, Codex, Gemini,
   Antigravity, and -- through one OpenAI-compatible adapter -- Ollama,
   OpenAI, Groq and xAI Grok. The endpoint path was 114 lines that had
   never run; it is now the fastest backend here and the only one whose
   wire format never had to be guessed.
9. Keys in the login keyring rather than a file, looked up by endpoint
   host and port so two services on one machine do not share one.
10. A remote agent: Hermes, over the same endpoint adapter, turning
    office lights on and off through Home Assistant by voice. Its
    tool-activity chunks passed through the parser, speech started
    before the tool finished and resumed after it, and the follow-up
    window carried the second command without a wake word.

Next, roughly in order of how much they matter:

9. Run the remaining adapters against live agents. The ten sharing the
   CLI adapter never have, and every one is an Omarchy mise stub here,
   so each needs a real install first. Their `remembers = False` is an
   inference from our own adapter yielding no session id, not a
   measurement of the CLI -- if one is ever installed, check whether it
   hands back a handle we are throwing away.

   The rate of wrong guesses so far: three in Gemini's adapter, none in
   Codex's, one security claim withdrawn from Antigravity's, and one
   Cloudflare block that made every Groq model unreachable. Flags read
   off `--help` are a hypothesis.
10. Antigravity is in Omarchy's default branch (`quattro`) but not in
    any release: `gemini` and `gemini-cli` alias to `agy` there, which
    is the name this already registers. Until that ships, selecting it
    means writing `~/.config/omarchy/defaults/agent` directly.
11. Widen the tests. `bin/agentvoice-check` runs 230, covering the
    speakable-text rules, the permission hook and its levels, config
    precedence, key resolution and scope, the adapter contract,
    process-tree teardown, and the recorded envelopes of the backends
    that have answered. The wake loop and the QML are still exercised
    only by hand.
12. A stranger at the microphone. The verifier's 0/12 against other
    speakers was synthetic, and a second voice in the room is the one
    failure mode that cannot be tested alone.
13. Conversation mode on a backend that forgets. The warning is
    verified; the behaviour behind it is not, because the only forgetful
    backend installed here is 503ing.

### Diagnosing a turn

The journal has the shape of every turn whatever the settings say -- wake
events, transcription and agent timings, tool markers, lock transitions,
errors:

```bash
journalctl --user -u agentvoice -f
```

The first line of each start says which build wrote the rest:

```
knobs: shell.json[duaneoca.agentvoice] · build 0.2.0 (3f9a1c2)
```

Worth checking before anything else, because the daemon and the bar widget
are installed separately and can therefore disagree. The widget arrives with
`omarchy plugin add` and updates with `omarchy plugin update`; the daemon is
whatever `install.sh` last copied, and the panel's install offer runs the one
in the plugin directory. So installing from a checkout and then clicking that
offer puts the published daemon back, and a line missing its `build` field is
a daemon from before this was recorded.

Every answered turn ends with the wait you actually sat through, and
where it went:

```
heard → spoke in 2.9s  (pause 1.1s · whisper 0.0s · claude warm 1.7s · first sentence 0.0s · voice 0.1s)
```

`warm` means the agent was already running when the prompt arrived; `cold`
means it had to be started for it, which costs Claude Code about a second.
The panel shows the same number as "answered in".

What it does **not** have is the words. `logSpeech` is off by default,
because the journal keeps entries for weeks and a reply is whatever the agent
read out. Three ways to turn it on when you need it:

```bash
# the switch, in Agent Voice settings: "Write what is said to the system log"
omarchy bar set duaneoca.agentvoice logSpeech true --json   # or from a shell
```

```toml
# or in ~/.config/agentvoice/agentvoice.toml, if you keep settings in a file
[ui]
log_speech = true
```

`--json` matters: without it the value is written as the string `"true"`
rather than a boolean. The daemon picks the change up on its next poll -- no
restart -- and `journalctl` shows "knobs updated" when it has. Turn it back
off the same way.

A terminal is a fourth way and needs no setting at all: run the daemon in
the foreground and it prints everything it hears and says, because somebody
is sitting there reading it.

```bash
agentvoice stop && ~/.local/share/agentvoice/venv/bin/python \
  ~/.local/share/agentvoice/app/daemon/wake_listen.py
```

For the wake word specifically, `agentvoice monitor --ab` scores each
utterance with and without your verifier and needs none of the above.

  daemon/
    paths.py              one place that resolves every path
    wake_listen.py        the loop: wake -> capture -> agent -> speech
    runtime.py            config, state file, speech
    speech_text.py        markdown -> speakable prose, sentence chunking
    crew.py               more than one agent: who is talking to whom
    agents_panel.py       each agent as a section in Omarchy's Agents panel
    verifier.py           train and load a personal verifier
    adapters/             base contract + claude_code, codex, gemini, ...
    agentvoice.toml       fallback config for non-Omarchy machines
    vocab.txt             default custom vocabulary
  desktop/
    agentvoice.service.in systemd user unit template

Everything the installer downloads -- interpreter, wheels, models, trained
verifiers -- lives under `~/.local/share/agentvoice/`, never in the repo.
